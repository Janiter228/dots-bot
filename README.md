# dots-bot

Бот для игры «Точки» (проектный практикум ИРИТ-РТФ, турнирный эмулятор).
Все работаем в своих ветках!!!

Публичный адрес бота и панели наблюдения — [https://d03.projectset.ru](https://d03.projectset.ru).

## Быстрый старт

```bash
npm start          # сервер на порту 4003 (нужен Node.js 20+)
npm test           # автотесты
```

Для развёртывания используйте Docker Compose: подготовьте `.env` по [инструкции запуска](docs/RUNBOOK.md), затем выполните `docker compose up -d --build`.

Панель наблюдения открывается в корне сервера (`http://localhost:4003/` или по публичному HTTPS-адресу). Метрики общедоступны, историю партий открывает отдельный `DASHBOARD_TOKEN`. Чтобы отключить раздачу страницы, задайте `SERVE_DASHBOARD=0`. Панель наблюдает за ответами и не вмешивается в игру бота.

Для проверки в «Песочнице» на сайте арены укажите `http://localhost:4003`.
Для «Проверки API» в кабинете укажите `https://d03.projectset.ru`. Проверка доступности — `GET https://d03.projectset.ru/v1/health`.

## Токены и переменные окружения

| Переменная | Назначение | Откуда берётся | Обязательность |
|---|---|---|---|
| `PORT` | HTTP-порт сервера бота | Выбирает команда; по умолчанию `4003`, под него настроен Compose | Необязательна |
| `BOT_TOKEN` | Защищает `POST /v1/move` | Из кабинета арены; значения должны совпадать | Оставьте пустым, пока токен не задан в кабинете |
| `DASHBOARD_TOKEN` | Открывает историю партий и последние ходы; `/api/status` открыт без токена | Отдельный пароль команды, арена о нём не знает | Нужен только для доступа к истории |

1. На сервере в корне проекта создайте `.env`: `cp .env.example .env` (в PowerShell — `Copy-Item .env.example .env`). Если файл уже есть, не перезаписывайте его.
2. Сгенерируйте пароль панели командой `openssl rand -hex 24` и запишите его в `DASHBOARD_TOKEN` в `.env`. Позже его можно посмотреть на сервере командой `grep DASHBOARD_TOKEN .env`. Она выводит секрет: не запускайте её в общем терминале и не пересылайте вывод.
3. Запустите контейнер командой `docker compose up -d`. Если контейнер уже работает, примените изменения `.env` командой `docker compose up -d --force-recreate dots-bot`.
4. Откройте панель по адресу бота (через HTTPS для публичного адреса), вставьте пароль в поле **«Токен панели»** и нажмите **«Войти»**. Пароль хранится только в памяти страницы; после обновления его нужно ввести снова.

`gameId` и `X-Arena-Run` — идентификаторы, а не секреты. Не коммитьте токены и `.env`: файл уже указан в `.gitignore`.

## Играть в браузере

1. Откройте `web/index.html` двойным щелчком в современном браузере. Локальная игра на двоих работает без сервера, библиотек и сборки.
2. Для игры с ботом выполните `npm start`, переключитесь в режим **«Против HTTP-бота»**, укажите адрес (по умолчанию `http://localhost:4003`) и свой цвет. Выберите размер поля и нажмите **«Новая партия»**.
3. Красные начинают. Ставьте точки щелчком по свободному пересечению или стрелками и Enter. Кнопка **«Вписать»** показывает всё поле, ползунок меняет масштаб.
4. Нажмите **«Показать захват»**, чтобы открыть учебный пример: четыре красные точки замыкают контур вокруг синей. Включите **«Карту окружений»**, чтобы увидеть замкнутые области, в том числе пустые.
5. В **«Разборе партии»** можно перемотать ходы ползунком, перейти по журналу или запустить автовоспроизведение. Просмотр не влияет на текущую позицию: клики по полю заблокированы, а кнопка **«К игре»** возвращает управление.
6. Кнопка **«Отменить ход»** возвращает позицию к предыдущему ходу; в игре с ботом ход бота откатывается вместе с вашим.

Страница отправляет `POST {адрес}/v1/move` в формате арены: `gameId`, `moveNo`, `you`, `field`, `points`, `dead`, `score`, `last`, `moveTimeoutMs`, `timeLeftMs`. Ответ `{x, y}` проверяется на границы и занятость, включая мёртвые точки.

### Журнал и красивая консоль

При `npm start` терминал показывает цветной стартовый блок: версию алгоритма, адрес, маршруты API, статус авторизации и подсказку запуска игры. Цвет включается в интерактивном терминале; при перенаправлении в файл вывод остаётся обычным текстом. Переменная `NO_COLOR` отключает цвет. Значение токена не выводится.

Справа на странице — последние 100 событий: ходы, время ответа и ошибки. В **F12 → Console** события сгруппированы и имеют цветные заголовки. Раскройте группу HTTP-запроса, чтобы увидеть отправленную позицию и ответ.

Проверить сервер отдельно в PowerShell:

```powershell
Invoke-RestMethod http://localhost:4003/v1/health | Format-List
```

### Если бот недоступен

- Проверьте, что `npm start` запущен, а адрес и порт совпадают с настройками страницы. Если браузер запросит доступ к локальной сети, разрешите его.
- HTTP-ошибка, недопустимый ответ или таймаут 5 секунд означают пропуск бота. После своего хода нажмите **«Продолжить: ход бота»** для повторного запроса. После 11 последовательных пропусков — техническое поражение бота.
- **«Новая партия»** отменяет текущий запрос; поздний ответ не применяется к новой позиции.
- Страница не передаёт токен авторизации. Для локальной игры используйте сервер без обязательного `BOT_TOKEN`.
- Если браузер блокирует запросы из локального файла и установлен Python, выполните `python -m http.server 8080 --bind 127.0.0.1` в корне проекта и откройте `http://127.0.0.1:8080/web/`. Сервер бота остаётся работать на 4003.

### Правила и конец партии

Захваты считаются в странице по областям четырёхсвязности. Стены — только живые точки цвета. Мёртвые точки сохраняют цвет и занимают пересечение, пустая территория очков не даёт. Окружения пересчитываются до стабильности с возможным оживлением. Партия завершается при заполнении поля или исчерпании общего бюджета ответов 15 минут. Победитель определяется по числу захваченных точек; время обдумывания человека не списывается.

**Проверка правил:** реализация ещё не сверена с эталонными правилами арены. Сначала обрабатывается цвет сделавшего ход, затем другой цвет. При цикле или превышении предела пересчёта партия останавливается с диагностикой. Совпадение счёта с песочницей для вложенных окружений не подтверждено.

## Тестирование

```bash
npm test
node --test tests/bot.test.mjs tests/regression.test.mjs
```

`npm test` запускает тесты алгоритма, регрессий, правил, HTTP API и панели наблюдения. Для API-тестов требуется возможность открывать локальные TCP-порты. При ошибке запуска тестового сервера проверки завершаются с диагностикой.

Проверки с эталонным движком организаторов требуют файла `dots.mjs`. Задайте абсолютный путь через `DOTS_ENGINE`. Проверки эталона пропускаются, если путь не задан.

```bash
DOTS_ENGINE=/absolute/path/dots.mjs node --test tests/rules.test.mjs
DOTS_ENGINE=/absolute/path/dots.mjs node tests/match.mjs > matches.json
DOTS_ENGINE=/absolute/path/dots.mjs DOTS_SIZES=10,20,30 DOTS_SEEDS=1,17,42 node tests/match.mjs > matches.json
```

По умолчанию запускаются 12 партий против случайного соперника с фиксированными seed: поля 10 × 10 и 20 × 20, seed 1, 17 и 42, каждый цвет бота. JSON-отчёт содержит счёт, число ходов, ошибки, среднее, p95 и максимальное время ответа, а также историю ходов. Ошибка или незавершённая партия дают ненулевой код выхода.

Seed фиксирует генератор соперника. Ограничение поиска бота по реальному времени может приводить к разным ходам на разных машинах. Для разбора сохраняйте отчёт конкретной партии. Подробности — в [tests/README.md](tests/README.md).

## Документация

По умолчанию работает самостоятельный алгоритм. DOTS_AI_MODE=hybrid включает двух обученных советников. MAX_RESPONSE_TIME_MS задаёт общий лимит запроса, по умолчанию 2000 мс. [Настройки и обучение](docs/AI_INTEGRATION_GUIDE.md) · [Матчи и измерения](docs/MATCH_REPORT.md).

Для обучения на собственных играх Compose сохраняет полные позиции и ответы в JSONL на постоянном томе. Выгрузка архива и контроль записи описаны в [RUNBOOK](docs/RUNBOOK.md#архив-игр-для-обучения). Архив сохраняется при деплое; обучение по нему подключается отдельно.

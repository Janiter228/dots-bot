# Dots Bot v0.3.1 — избегание закрытых территорий

## Новое поведение

Перед ранжированием ходов бот дважды анализирует компоненты поля flood fill по четырём направлениям:

1. Территории, замкнутые живыми точками текущего игрока.
2. Территории, замкнутые живыми точками соперника.

Клетки обеих масок исключаются из обычного списка кандидатов.

- Ход в территорию соперника обычно сразу превращает поставленную точку в мёртвую и увеличивает счёт соперника.
- Ход в собственную закрытую территорию не даёт захвата и расходует очередь; пустую клетку выгоднее сохранить как ловушку для возможной точки соперника.

Если у фронтира нет безопасных кандидатов, бот ищет любую свободную клетку вне обеих закрытых территорий. Если все свободные пересечения находятся внутри закрытых территорий, бот всё равно возвращает свободную клетку: по протоколу пасовать нельзя.

## Соответствие правилам

Для поиска зон используется то же базовое определение из спецификации арены: связность пустых/не принадлежащих стене клеток по четырём направлениям, а стенами считаются только живые точки проверяемого цвета. Мёртвые точки не являются стенами.

Это изменение влияет на выбор кандидатов и не меняет HTTP API. Оно не заменяет полный эталонный движок и не решает отдельно все случаи вложенного повторного захвата.

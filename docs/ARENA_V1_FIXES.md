# Исправления и проверки для Arena v1

В этой задаче проверяется готовность бота к раунду «Точки» на конечном поле 100×100. Основание — аудит ветки `qa` на коммите `8580db0`. [Спецификация Arena v1](https://arena.projectset.ru/docs?p=dots) · [OpenAPI](https://arena.projectset.ru/docs?p=dots%2Fopenapi.yaml)

## 1. Высокий приоритет — одинаковый ответ на повтор хода

В `server/index.js` каждый `POST /v1/move` заново вызывает `chooseMove`. В `bot/index.js` глубина поиска зависит от времени выполнения. При проверке одна позиция 50×50 со 100 точками и лимитом 50 мс дала три разных допустимых хода за восемь вызовов. Раздел 3.2 требует, чтобы повтор того же `moveNo` возвращал те же координаты.

- **Исправление.** Сохранять первый допустимый ответ по `(gameId, moveNo)` на время партии либо сделать выбор детерминированным. Если сервис работает в нескольких процессах, использовать общее хранилище ответа или детерминированный выбор.
- **Приёмка.** HTTP-тест отправляет одну позицию несколько раз с одинаковыми `gameId`, `moveNo` и `X-Arena-Seq` и получает `200` с одинаковыми координатами. Отдельная проверка подтверждает, что запрос с тем же `moveNo` в другой партии обрабатывается независимо. Тест должен проверять повтор на позиции с несколькими свободными клетками.

## 2. Средний приоритет — вложенные захваты и оживление точек

В `bot/index.js` функция `applyMove` помечает захваченные точки за один проход. По правилам Arena захваты пересчитываются до стабилизации, и ранее захваченные точки могут ожить. Упрощённая симуляция влияет на оценку позиции. В `web/index.html` используется собственный пересчёт правил, который ещё нужно сверить на вложенном окружении.

- **Исправление.** Воспроизвести сценарий на эталонном движке, затем привести симуляцию хода и, при выявленном расхождении, пересчёт в веб-интерфейсе в соответствие с ним.
- **Приёмка.** Регрессионный сценарий содержит ранее захваченную точку и ход, замыкающий внешний контур вокруг вражеских стен. После хода наборы мёртвых точек обоих цветов и счёт совпадают с эталоном. Добавить HTTP-сценарий для той же позиции до хода и проверить, что бот возвращает свободное пересечение. [Эталонный движок Arena](https://arena.projectset.ru/engine/dots.mjs)

## 3. Низкий приоритет — служебные ответы API

- **`POST /v1/game/start`.** Сейчас общий обработчик возвращает `405`. Для необязательного маршрута OpenAPI предусматривает `404`, если обработчика нет, или `200` при успешной обработке. Исправить ответ и закрепить выбранное поведение HTTP-тестом.
- **`GET /v1/info`.** Сейчас сервер отдаёт `version: "0.3.1"`, а алгоритм объявляет `BOT_VERSION = "0.3.2"`. Использовать `BOT_VERSION` в ответе. Тест проверяет совпадение `version` с `BOT_VERSION` и значение `specVersion: "v1"`.

## 4. Приёмка на Arena

1. Запустить `DOTS_ENGINE=/абсолютный/путь/dots.mjs npm test` с официальным движком. Проверить, что тесты v1 проходят и тесты правил запускаются.
2. Указать публичный URL сервиса без редиректов в кабинете Arena и выполнить «Проверить API». Сохранить отчёт по пустому полю, почти заполненному полю и позиции с мёртвыми точками.
3. Сыграть тренировку 100×100 за оба цвета. В журнале проверить допустимость ходов, отсутствие пропусков по вине бота и время HTTP-ответов с учётом сети в пределах `moveTimeoutMs`. Лимит первого раунда — 5000 мс.
4. Доиграть партию в веб-интерфейсе и проверить финальный счёт, завершение партии и блокировку ходов после окончания.

До исправлений с официальным движком прошли 30 тестов, один тест безграничного режима отмечен `todo`. Две локальные партии 10×10 против воспроизводимого случайного соперника завершились без ошибок. На четырёх искусственных позициях 100×100 выбор допустимого хода занимал 420–512 мс без учёта HTTP. Публичный прогон, партии 100×100 и завершение партии в веб-интерфейсе остаются в плане приёмки.

Поддержка `field.infinite` в HTTP API и исправление хода в центр чужого ромба относятся к отдельной задаче для безграничного режима v2.

# Стратегия бота — игра в точки

Документ описывает реализованное в `bot/index.js`. При расхождении решающим остаётся результат эталонного движка арены.

## 1. Правила игры и модель поля

### 1.1 Суть игры

В первом раунде поле 100×100. Красные ходят первыми. Ход — постановка точки на свободное пересечение; пасовать нельзя. Заняты все клетки с точками, включая мёртвые. Счёт — число мёртвых точек противника. Партия заканчивается при заполнении поля, по общему таймеру (15 минут на ответы обеих команд в первом раунде) или после более 10 пропусков подряд.

### 1.2 Как работает захват

Диагональная цепочка живых точек может разделять области. Край поля не является стеной. Пустая окружённая область очков не даёт, но поставленная туда вражеская точка сразу погибает. Арена пересчитывает окружения до стабилизации; ранее мёртвые точки могут ожить.

Формальная проверка захвата: рассматриваем все пересечения, где нет живой точки атакующего цвета, и разбиваем их на области связности по четырём направлениям. Если из области нельзя выйти за край поля, она окружена; живые точки противника внутри неё захватываются. Мёртвые точки не являются стенами и не участвуют в контурах.

### 1.3 Структура входных данных

Бот получает JSON-объект `request`:

```js
{
  gameId: "game-1",
  moveNo: 1,
  you: "red",                 // цвет бота
  field: { width: 100, height: 100 },
  points: {
    red: [],                  // все точки, включая мёртвые
    blue: [],
  },
  dead: { red: [], blue: [] }, // координаты захваченных точек
  score: { red: 0, blue: 0 },
  last: null,                 // необязательно: [x, y] последнего хода
  moveTimeoutMs: 5000,        // необязательно
  timeLeftMs: 900000,         // необязательно: общий остаток партии
}
```

Бот возвращает `{ x, y }` — координаты хода, либо `null` (сервер поставит запасной ход сам).

Координаты конечного поля: (0, 0) — верхний левый угол, ось X вправо, ось Y вниз. Бот не хранит состояние между ходами.

## 2. Выбор хода в v0.3.3

- Бот предпочитает клетки вне контуров обоих цветов, затем клетки внутри своего, но не чужого контура. Если свободные клетки остались только внутри чужих контуров, бот всё равно ходит.
- Поиск точек сочленения в графе доступных из-за края клеток находит немедленные захваты по всему полю, не ограничиваясь позиционным рейтингом. Единственный захват без встречной угрозы или единственный безопасный прямой блок без своего захвата возвращается сразу.
- На лучших полностью проверенных ветках поиск пробует захваты и прямые блоки на третьем полуходе, затем проверяет сильнейший немедленный контрзахват на четвёртом. После хода-вилки блок одной клетки не скрывает вторую угрозу; встречный захват может снять обе. Поиск выборочный, не гарантирует нахождение всех вилок.
- При единственной немедленной угрозе прямой блок проверяется первым. Если найден ход, после которого соперник не может немедленно захватить нашу точку, тактический размен не вытесняет его. Когда безопасной защиты нет, поиск сравнивает доступные размены обычной оценкой.
- Мягкий бюджет — минимум из 475 мс, 52% `moveTimeoutMs` (по умолчанию 5000 мс) и `timeLeftMs / 120` при наличии общего таймера. Легальная клетка найдена до поиска; если углубление прервано, сохраняется результат основного поиска.
- Веса ранжирования, захватов, потерь, живых точек, связности и фронтира собраны в `WEIGHTS`. Подбор самоигрой не проводился.
- Для `field.infinite` бот использует `Map` занятых координат и `Set` соседних кандидатов. Это задел: тактика и подсчёт окружений не перенесены, сервер этот режим пока не поддерживает.

## 3. Результаты и ограничения

| Проверка | Результат |
|---|---|
| Песочница, 50×50, красные против «Окружателя» | По скриншоту: победа 730:13, 2500 ходов. Это не прогон v0.3.2. |
| Локальные тесты | Вилка, контрзахват, исчерпанный таймер, вынужденный ход в закрытую зону и разреженное поле проверяются в `tests/bot.test.mjs`. |
| Регрессии защиты | Две воспроизводимые позиции, где v0.3.1 блокирует потери, а v0.3.2 выбирал размен; v0.3.3 выбирает ход без немедленной потери. |
| Бенчмарк 100×100 | Исходно 548–695 мс; после доработки около 380–480 мс, все четыре хода допустимы. |
| «Тренировка» и матчи с предыдущей версией | Не проведены. 100 побед на соперника и 95% против предыдущей версии не подтверждены. |

Финальный скриншот не показывает, какие из 13 красных точек захватил соперник, а какие были поставлены в уже окружённые зоны. Локальные тесты воспроизводят отдельные сценарии, а не позиции из этой партии. Для точного разбора нужен пошаговый журнал `points` и `dead`.

Эталонного движка нет, `engine/adapter.js` и `web/index.html` пусты. Вложенные окружения и оживление не сверялись; интерфейс и сравнение счёта с песочницей не реализованы.
